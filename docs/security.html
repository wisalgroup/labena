Security

Supported versions#

Bug and security fixes target only the latest published non-prerelease version; older versions receive no backports. Maintenance is best effort, with no guaranteed response or resolution time. Before the first release, development snapshots have no stable support commitment. See support and compatibility.

Report a vulnerability privately#

Report vulnerabilities through GitHub private vulnerability reporting. You can also open Security → Advisories → Report a vulnerability in the repository. A customized application may have a different owner and reporting channel; report application-specific issues to that owner.

Include the affected tag or commit, impact, reproduction steps and a minimal proof of concept with synthetic data. Do not post credentials, personal data or exploitable production details in public issues. If the private reporting button is unavailable, do not substitute a public issue containing vulnerability details.

Wisal Group's repository maintainers are responsible for monitoring reports, assessing impact, coordinating a fix and publishing an advisory with affected/fixed versions and adoption instructions. Customized applications must incorporate those fixes themselves.

Private vulnerability reporting is enabled for the public repository. Its setting and public reporting entry point were verified on 2026-10-18. Repository maintainers must keep report notifications enabled and monitor incoming reports. Notification delivery has not been tested by submitting a report. Follow GitHub's setup instructions.

Application security#

Use placeholder credentials in examples. Rotate accidentally exposed credentials. Enable authentication deliberately, restrict administrative endpoints, and review deployment secrets and network policies before exposing an application.

Run govulncheck ./... with the declared Go toolchain when updating dependencies. A passing scan does not replace authorization, integration and concurrency tests.
